## Composition and hierarchy

The first impression is a short editorial introduction followed by a dominant coastal footage viewer. Keep generous white space around the introduction, then give the actual imagery substantially more area than the surrounding controls. The product should be understandable before an account is requested.

- Use option 2's lighter, regular editorial sans display treatment, including its restrained tracking and open spacing. Do not inherit option 3's heavy bold headline. The generated image is a visual reference, not an identified or licensed font specification.
- Keep the headline concise, with one supporting sentence. Restrict strong weight to small functional labels where hierarchy requires it.
- Use option 3's large rocky-coast view as the main image reference. The viewer, a compact filmstrip and a restrained range-control row form one connected surface.
- Remove the simultaneous Sources and Moments sidebars from the landing preview. Reveal source navigation or moment context only when needed in the real product.
- Remove decorative badges, persistent save-success badges, repeated play/time displays, repeated calls to action and explanatory footer text beneath the preview.
- Present one emphasized primary action, “Start a project,” once on the landing page. Keep Sign in as a quiet navigation link. Demonstration controls remain subordinate; save feedback appears only after an actual save interaction.
- Retain a compact Light / Dark / System control in the header, with the selected state legible. Light remains the default; System applies only when selected.
- Use thin dividers only where they clarify a real boundary. Avoid nesting bordered cards around controls that already belong to the same viewer.

The demo must use deliberately public sample media and local sample data if implemented. Generated coastal imagery is illustrative and is not evidence of an available video asset or working interaction.

## Logo direction

Propose a bespoke monochrome mark combining an open frame with one deliberate diagonal cut that suggests an R. Pair it with a clean RUSHES wordmark whose spacing complements the regular display typography.

- Aim for recognition at 24px: one clear silhouette, sturdy strokes and open negative space. Avoid film sprockets, multiple tiny cuts, enclosing app tiles and gradients.
- Use the same geometry in light and dark appearances through contrasting foreground color, rather than separate decorative logos.
- Design the mark to stand alone in constrained navigation and work beside the wordmark at larger sizes. Verify the actual vector at 24px before accepting it; a generated mockup alone cannot establish small-size legibility or distinctiveness.

## Carrying the hierarchy through the product

| Surface | Proposed refinement |
|---|---|
| Login and signup | Reuse the mark, regular heading and quiet background. Show one form with one submit action; retain distinct routes, requirements and inline errors. Keep appearance choice accessible. |
| First project and import | Give the current question or upload task priority. Show only the next relevant action and essential processing/storage context. Retain explicit creation, recovery IDs and truthful progress. |
| Library | Put footage and its useful metadata first. Reveal import, search and collection actions in their existing context without permanent explanatory panels. |
| Player and selects | Preserve the large viewer and connected range controls. Show source navigation or worklog context as one focused secondary region; expose extra context on demand. Preserve labeled In/Out inputs and inline first-Selects creation. |
| Export | Use a focused review state with explicit Start export; when ready, make the real download primary in the existing queue item. Preserve failure history and the editor-interchange disclosure. |
| Mobile | Stack introduction, viewer and controls. Put supplementary review context below the viewer or in a labeled sheet. Preserve 44px touch targets, numeric range inputs, visible focus and an accessible appearance control. |

## Visual validation

Review the revised mockup for regular headline weight, image dominance, a single landing primary action and a recognizable logo. Then develop light/dark and mobile studies from the accepted direction. Essential errors, upload guidance, media permissions and export disclosures must remain visible where the user needs them.

Material risks: a generated logo may lose clarity at small sizes; the exact font remains to be selected; and reducing visible panels must preserve discoverability of source navigation and timestamped evidence. Validate these through vector inspection and real responsive interactions, not additional decorative copy.
